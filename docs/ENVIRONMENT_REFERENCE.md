## Phase B implemented configuration boundary

- Frontend production builds require an explicit HTTPS `VITE_API_BASE_URL` without credentials, or exactly `/api`. Missing values, localhost and unsafe schemes fail the build. Development retains its intentional localhost fallback. Validation used `$env:VITE_API_BASE_URL='/api'; npm.cmd run build`; a same-origin `/api` proxy must actually be provided by later deployment work. No proxy was configured in Phase B.
- Backend `validateEnvironment` rejects invalid NODE_ENV values. With NODE_ENV=production, DATABASE_URL must be PostgreSQL, REDIS_URL Redis, FRONTEND_URL one exact HTTP(S) origin without path/credentials/wildcard, and PORT within1-65535. Values are never printed. Deployment must explicitly set NODE_ENV=production; transport/private-network policy remains Phase C.
- Any configured Cloudinary field requires all four fields in production. All absent retains the existing unavailable-media503 behavior; enabled uploads require complete credentials and separately verified account/preset policy. No new media-disable flag or authentication behavior was introduced.
- The new backend sanitizer is sanitize-html2.18.0, requiring Node>=22.12.0. The locally verified runtime is22.12.0. Existing eslint-visitor-keys warns that it needs22.13+; choosing/validating the production runtime remains the deployment gate, with no major package upgrade here.
- Standard public CMS pages now require PUBLISHED just like details. The existing development Home/Solutions records remain DRAFT and intentionally return404 until their publication is reviewed through existing admin controls. Browser fixtures mark standard pages published only in memory; no seed or publication migration ran.


## Phase C configuration and runtime contract

Completed source pass2026-10-09. Earlier Phase A/B statements above are historical; this section supersedes their runtime-policy gaps. No infrastructure was provisioned.

- Production must explicitly inject NODE_ENV=production before running npm run start:prod. That command rejects any other/missing mode before loading the compiled dist/src/main.js entry. Development start/watch still uses local dotenv normally.
- Production startup requires PORT1-65535, DATABASE_URL with PostgreSQL protocol, REDIS_URL with Redis protocol, FRONTEND_URL as exactly one HTTPS origin, and TRUST_PROXY as explicit comma-separated IPs/CIDRs. Errors name configuration keys without values. CORS and Origin use the same origin; staging uses its own exact HTTPS origin and credentials, not an expanded wildcard. Private endpoints, authenticated Redis, provider TLS and secret-manager injection are mandatory Phase D gates, not established by URL syntax validation.
- Example TRUST_PROXY=127.0.0.1/32,::1/128 applies only to a reverse proxy on the same backend host. Set actual private reverse-proxy IPs/subnets; include CDN ranges only when those addresses legitimately appear in the sanitized forwarded chain. No arbitrary boolean/hop-count trust. Omitted development trust is false.
- Session configuration is intentionally fixed in code:32 random bytes encoded base64url, SHA-256 Redis key suffix,8-hour absolute session TTL, no sliding refresh, current active-user/current-role DB check. Production session cookie is __Host-neotek_admin_session, HttpOnly/Secure/SameSite=Lax/Path=/ with no Domain. Logout clears matching flags and deletes both session and CSRF keys. Secure=false is allowed only for nonproduction HTTP localhost/127.0.0.1/::1. HTTPS development and nonlocalhost configurations retain Secure.
- SameSite=Lax requires frontend/API to be same-site HTTPS, preferably a same-origin /api proxy. A completely cross-site API is not supported by silently switching to SameSite=None. CSRF is server-session-scoped, atomically reused and expires no later than the Redis session; a later CSRF cookie does not extend server authentication.
- All Cloudinary fields absent means uploads unavailable503; any configured field requires all four. Media uses image/upload, restricted signed formats, unique neotek/cms IDs and overwrite=false. A signed preset must independently enforce10MB, image-only formats/resources, account permissions/quota and restricted delivery/transformation policy. Client10MB checks are not proof of account enforcement; verify in Phase D without exposing API secret.
- JSON limit2MiB; URL-encoded limit64KiB with100 parameters; Nest default parser is disabled before registering these parsers. CMS recursive validation rejects more than32 JSON nesting levels or50000 visited values before Zod recursion. Existing strict Zod schemas/manual DTO checks remain authoritative; no blind ValidationPipe stripping or coercion.
- Redis startup wait3s; socket connect timeout2s; per-command deadline2s; offline queue disabled and command queue capped100. Reconnect delay rises to3s maximum. Startup may be degraded while reconnect continues: public cache reads/writes fall back to DB, auth/rate checks fail closed, readiness503. On command timeout the socket is discarded rather than replaying queued mutations; outcome may be unknown if Redis had already committed, so callers do not retry security mutations blindly. Graceful Redis quit is bounded2s then destroy.
- /api/health/live is process liveness without dependency probes. /api/health and /api/health/ready are readiness: DB and session-critical Redis must be usable;200 healthy,503 degraded, dependency probes bounded2s. Readiness exposes only up/down dependency labels, never errors/DSNs. A deadline does not cancel a Prisma query: configure actual connection/pool/socket limits in Phase D. Shared Redis remains session-critical even when public cache can degrade.
- SIGTERM/SIGINT mark the service draining, reject new work503 (liveness remains200), and invoke Nest provider/server shutdown. Prisma disconnects and Redis closes. Fatal uncaught exceptions/rejections terminate nonzero with redacted diagnostics; the supervisor must restart. No attempt to continue a corrupted process. Configure a finite supervisor termination grace window in Phase D.
- Login limits5/IP/minute and20/normalized-account/minute; account/IP identifiers are hashed. Authenticated media signing20/user/minute, CSRF acquisition120/user/minute and admin mutations120/user/minute. No public CMS GET throttle was added. Redis failure rejects rate verification503; session store failures remain safe500, not a false401 that would log users out.
- Logs include Nest timestamp/level plus method, route template, status, durationMs and generated requestId. Never log body/query/cookies/authorization/CSRF/credentials or raw dependency messages/stacks. Request IDs are generated by the backend rather than trusting incoming values. Monitoring/alert routing and private diagnostic tooling remain Phase D.
- API CSP: default-src 'none', frame-ancestors 'none', base-uri 'none', form-action 'none', object-src 'none'; no unsafe-inline. API Helmet adds HSTS/nosniff/referrer policy; Permissions-Policy disables camera/microphone/geolocation. This policy governs JSON API responses, not separately hosted frontend HTML. Auth/admin responses use no-store, including errors.
- Frontend production source maps explicitly disabled; final dist contains zero .map files. No frontend console logging remains in src. Node engines in both manifests retain major22 (>=22.12.0 <23), the minimum compatible with the existing sanitizer. Local verification used22.12.0; production must pin a current patched22.x, not promote this old local binary. Node22 is Maintenance LTS through2027-04-30: https://github.com/nodejs/Release . eslint-visitor-keys additionally expects22.13+; choose a current patched22.x for Phase D.
- Prisma client/CLI remain6.19.0 with the existing package.json#prisma seed configuration. Deprecation is deliberately deferred: moving operational seed configuration is unnecessary for security fixes and was not tested by executing seed. No Prisma7 upgrade, schema edit, seed or migration ran.
